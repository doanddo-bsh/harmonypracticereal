# Phase 2: CI/CD 구성 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** PR마다 정적 분석·테스트·양 플랫폼 빌드가 자동 검증되고, 태그를 밀면 Android는 Play Internal 트랙에, iOS는 TestFlight에 자동 업로드된다.

**Architecture:** GitHub Actions를 오케스트레이터로, Fastlane을 스토어 업로드 실행기로 쓴다. 워크플로는 3개로 분리한다 — `ci.yml`(모든 PR·push에서 분석/테스트/빌드), `release-android.yml`(태그 시 Play 업로드), `release-ios.yml`(태그 시 TestFlight 업로드). 서명 키와 Firebase 설정 파일은 저장소에 넣지 않고 GitHub Secrets에 base64로 넣어 워크플로 실행 중에 복원한다.

**Tech Stack:** GitHub Actions, Fastlane (supply / pilot), `subosito/flutter-action`, Google Play Developer API 서비스 계정, App Store Connect API 키

**전제 조건:** Phase 1이 완료되어 있어야 한다. 특히 `flutter build appbundle --release` 와 `flutter build ios --release --no-codesign` 이 로컬에서 성공해야 한다.

## 착수 전 현황 반영 (2026-08-04)

Phase 1 을 끝내면서 이 계획서 작성 시점의 전제가 몇 가지 바뀌었다. **아래를 반영해서 진행할 것.**

**1. `FLUTTER_VERSION` 은 3.44 이상이어야 한다 (하드 요구사항).**
`pubspec.lock` 의 SDK 하한이 `dart: >=3.12.0` / `flutter: >=3.44.0` 으로 올라갔다 (`async_preferences 2.0.0` 이 선언). 이보다 낮추면 CI 가 `flutter pub get` 단계에서 실패한다. 아래 워크플로들의 `FLUTTER_VERSION: '3.44.2'` 는 조건을 만족하지만, 임의로 낮추면 안 된다.

**2. iOS 는 Swift Package Manager 로 이전됐다.**
Flutter 3.44 의 마이그레이터가 적용했고, 이제 **`Flutter` 자체만 CocoaPod** 이며 나머지 플러그인은 전부 SPM 이다 (`pod install` 출력: `1 dependency ... 1 total pod installed`). 계획서의 iOS 워크플로가 CocoaPods 중심으로 쓰여 있으니:
- `pod install` 은 여전히 필요하다 (Flutter 자체를 위해) — 지우지 말 것
- SPM 체크아웃 캐시(`~/Library/Caches/org.swift.swiftpm`, `build/ios/SourcePackages`)를 캐시 대상에 추가하면 빌드가 빨라진다
- `ios/*/Package.resolved` 가 커밋돼 있고, `Podfile.lock` 이 한 항목뿐이라 **iOS 네이티브 SDK 버전을 실제로 고정하는 것은 `Package.resolved`** 다

**3. 저장소가 PUBLIC 이다.**
GitHub Actions 사용 시간이 무료 무제한이므로 macOS 러너(분당 요금이 비싼 편) 사용에 대한 비용 제약이 없다. 다만 소스가 공개이므로 시크릿이 로그에 찍히지 않도록 주의할 것 — `echo "${{ secrets.X }}"` 를 그대로 출력하는 스텝을 만들지 말 것.

**4. `gh` CLI 가 인증돼 있다** (`doanddo-bsh`, `repo` 스코프). 시크릿을 웹 UI 대신 `gh secret set` 으로 등록할 수 있다.

**5. Android 쪽 시크릿 재료는 이미 로컬에 있다.**
`keystore/key.jks`(별칭 `harmonypracticekey`), `android/key.properties`, `android/app/google-services.json` 전부 배치돼 있고 gitignore 로 보호된다. Task 3 의 시크릿 생성은 바로 가능하다.

**6. iOS 인증서는 폐기됐을 가능성이 높다.**
Apple 개발자 계정이 만료됐다 재결제된 이력이 있다. Task 4 착수 전에 `security find-identity -v -p codesigning` 으로 배포 인증서 유효성부터 확인할 것. 없으면 재발급이 선행돼야 한다.

**권장 진행 순서:** Task 1(검증 워크플로) → Task 2(Fastlane) → Task 3(Android 배포) → **여기서 한 번 실제로 돌려보고** → Task 4(iOS 배포, 인증서 확인 후) → Task 5·6.

- [ ] **Step 3: CI 워크플로 작성**

`.github/workflows/ci.yml` 를 생성:

```yaml
name: CI

on:
  push:
    branches: [main]
  pull_request:
    branches: [main]
  workflow_dispatch:

env:
  FLUTTER_VERSION: '3.44.2'

jobs:
  analyze-and-test:
    name: 정적 분석 및 테스트
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4

      - uses: subosito/flutter-action@v2
        with:
          flutter-version: ${{ env.FLUTTER_VERSION }}
          channel: stable
          cache: true

      - name: 의존성 설치
        run: flutter pub get

      - name: 정적 분석
        # error 가 하나라도 있으면 실패한다. info/warning 은 통과시킨다.
        run: flutter analyze --no-fatal-infos --no-fatal-warnings

      - name: 테스트
        run: flutter test --reporter expanded

  build-android:
    name: Android 빌드
    runs-on: ubuntu-latest
    needs: analyze-and-test
    steps:
      - uses: actions/checkout@v4

      - uses: actions/setup-java@v4
        with:
          distribution: temurin
          java-version: '17'

      - uses: subosito/flutter-action@v2
        with:
          flutter-version: ${{ env.FLUTTER_VERSION }}
          channel: stable
          cache: true

      - name: Firebase 설정 복원
        # Secrets 가 없으면 이 스텝을 건너뛰고, 다음 스텝에서 빌드가 실패한다.
        # 시크릿을 넣기 전까지는 이 잡이 빨간불인 게 정상이다.
        env:
          GOOGLE_SERVICES_JSON: ${{ secrets.GOOGLE_SERVICES_JSON }}
        run: |
          if [ -z "$GOOGLE_SERVICES_JSON" ]; then
            echo "::warning::GOOGLE_SERVICES_JSON 시크릿이 없어 Android 빌드를 건너뜁니다"
            exit 0
          fi
          echo "$GOOGLE_SERVICES_JSON" | base64 --decode > android/app/google-services.json

      - name: 의존성 설치
        run: flutter pub get

      - name: 디버그 AAB 빌드
        # PR 검증 단계에서는 서명이 필요 없는 debug 로 컴파일 가능 여부만 본다.
        run: flutter build appbundle --debug

  build-ios:
    name: iOS 빌드
    runs-on: macos-15
    needs: analyze-and-test
    steps:
      - uses: actions/checkout@v4

      - uses: subosito/flutter-action@v2
        with:
          flutter-version: ${{ env.FLUTTER_VERSION }}
          channel: stable
          cache: true

      - name: Firebase 설정 복원
        env:
          GOOGLE_SERVICE_INFO_PLIST: ${{ secrets.GOOGLE_SERVICE_INFO_PLIST }}
        run: |
          if [ -z "$GOOGLE_SERVICE_INFO_PLIST" ]; then
            echo "::warning::GOOGLE_SERVICE_INFO_PLIST 시크릿이 없어 iOS 빌드를 건너뜁니다"
            exit 0
          fi
          echo "$GOOGLE_SERVICE_INFO_PLIST" | base64 --decode > ios/Runner/GoogleService-Info.plist

      - name: 의존성 설치
        run: flutter pub get

      - name: CocoaPods 설치
        run: cd ios && pod install --repo-update

      - name: 서명 없이 iOS 빌드
        run: flutter build ios --release --no-codesign
```

```ruby
default_platform(:ios)

platform :ios do
  desc "TestFlight 업로드"
  lane :beta do
    # App Store Connect API 키로 인증한다 (2FA 없이 CI에서 동작).
    api_key = app_store_connect_api_key(
      key_id: ENV["ASC_KEY_ID"],
      issuer_id: ENV["ASC_ISSUER_ID"],
      key_content: ENV["ASC_KEY_CONTENT"],
      is_key_content_base64: true,
      in_house: false
    )

    # 임시 키체인을 만들어 인증서를 격리한다. CI 러너에서 필수.
    setup_ci if ENV["CI"]

    match(
      type: "appstore",
      readonly: true,
      api_key: api_key
    )

    # versionCode 충돌을 막기 위해 TestFlight 의 최신 빌드 번호 + 1 을 쓴다.
    increment_build_number(
      build_number: latest_testflight_build_number(api_key: api_key) + 1,
      xcodeproj: "Runner.xcodeproj"
    )

    build_app(
      workspace: "Runner.xcworkspace",
      scheme: "Runner",
      export_method: "app-store",
      output_directory: "../build/ios/ipa"
    )

    upload_to_testflight(
      api_key: api_key,
      skip_waiting_for_build_processing: true
    )
  end
end
```

## Task 3: Android 배포 워크플로

**Files:**
- Create: `.github/workflows/release-android.yml`

**필요한 GitHub Secrets:**

| 이름 | 내용 | 만드는 법 |
|---|---|---|
| `GOOGLE_SERVICES_JSON` | `android/app/google-services.json` 의 base64 | `base64 -i android/app/google-services.json \| pbcopy` |
| `ANDROID_KEYSTORE_BASE64` | 릴리스 키스토어 `.jks` 의 base64 | `base64 -i keystore/<파일>.jks \| pbcopy` |
| `ANDROID_KEY_PROPERTIES` | `key.properties` 내용의 base64 | 아래 Step 2 참조 |
| `PLAY_STORE_JSON_KEY` | Play Developer API 서비스 계정 JSON | Google Cloud Console → 서비스 계정 → 키 생성 |

- [ ] **Step 1: 키스토어 위치 확인**

```bash
ls -la keystore/ 2>/dev/null
cat android/key.properties 2>/dev/null || cat android/app/key.properties 2>/dev/null
```

키스토어 파일이 로컬에 없으면 **여기서 멈춘다.** 원본 키스토어가 없으면 기존 Play 앱에 업데이트를 올릴 수 없다 (Play 앱 서명을 쓰고 있다면 업로드 키 재설정이 가능하므로, Play 콘솔 → 설정 → 앱 서명에서 확인).

- [ ] **Step 2: 시크릿 값 생성**

각 명령의 출력을 GitHub 저장소 → Settings → Secrets and variables → Actions 에 등록한다.

```bash
# 1. GOOGLE_SERVICES_JSON
base64 -i android/app/google-services.json | pbcopy
echo "GOOGLE_SERVICES_JSON 클립보드에 복사됨"
```

```bash
# 2. ANDROID_KEYSTORE_BASE64  (경로는 Step 1에서 확인한 실제 경로로)
base64 -i keystore/<키스토어파일>.jks | pbcopy
echo "ANDROID_KEYSTORE_BASE64 클립보드에 복사됨"
```

```bash
# 3. ANDROID_KEY_PROPERTIES
#    storeFile 경로를 CI 러너 기준(워크플로가 복원할 위치)으로 바꿔서 넣는다.
cat <<'EOF' | base64 | pbcopy
storePassword=<실제 비밀번호>
keyPassword=<실제 비밀번호>
keyAlias=<실제 별칭>

echo "ANDROID_KEY_PROPERTIES 클립보드에 복사됨"
```

`PLAY_STORE_JSON_KEY` 는 Google Cloud Console에서 만든 서비스 계정 JSON을 **그대로(base64 아님)** 붙여넣는다. 만드는 절차:
1. Play 콘솔 → 설정 → API 액세스 → 새 서비스 계정 생성
2. Google Cloud Console에서 해당 계정에 키 추가(JSON)
3. Play 콘솔로 돌아와 그 계정에 "릴리스 관리" 권한 부여

>
> Phase 3 Task 6 에서 광고 단위 ID 를 `--dart-define` 주입으로 바꿨다. 주입하지 않으면
> **구글 테스트 광고가 뜬다 — 즉 출시본의 광고 수익이 0 이 된다.**
>
> `release-android.yml` 에는 시크릿이 없으면 빌드를 하드 실패시키는 가드와,
> 빌드된 AAB 의 AOT 스냅샷에서 주입된 ID 를 확인하는 검증 스텝이 들어가 있다.
> **iOS 워크플로에도 같은 두 가지를 넣어야 한다:**
>
> ```yaml
>         env:
>           ADMOB_BANNER_IOS: ${{ secrets.ADMOB_BANNER_IOS }}
>           ADMOB_INTERSTITIAL_IOS: ${{ secrets.ADMOB_INTERSTITIAL_IOS }}
>         run: |
>           if [ -z "$ADMOB_BANNER_IOS" ] || [ -z "$ADMOB_INTERSTITIAL_IOS" ]; then
>             echo "::error::ADMOB_*_IOS 시크릿이 없습니다. 이대로 빌드하면 스토어 빌드가 테스트 광고를 띄웁니다(수익 0)."
>             exit 1
>           fi
>           flutter build ios --release --no-codesign \
>             --dart-define=ADMOB_BANNER_IOS="$ADMOB_BANNER_IOS" \
>             --dart-define=ADMOB_INTERSTITIAL_IOS="$ADMOB_INTERSTITIAL_IOS"
> ```
>
> 두 시크릿은 **이미 등록돼 있다**. 이 워크플로가 생기기 전까지 iOS 는 수동 빌드이며,
> 그 경우 위 `--dart-define` 두 개를 손으로 붙이지 않으면 수익이 0 이 된다.
> `docs/RELEASE.md` 에도 경고가 있지만 문서는 워크플로의 하드 가드보다 약하다.

```yaml
  push:
    tags:
      - 'v*.*.*'
  workflow_dispatch:

env:
  FLUTTER_VERSION: '3.44.2'

jobs:
  release:
    name: TestFlight 업로드
    runs-on: macos-15
    steps:
      - uses: actions/checkout@v4

      - uses: ruby/setup-ruby@v1
        with:
          ruby-version: '3.3'
          bundler-cache: true

      - uses: subosito/flutter-action@v2
        with:
          flutter-version: ${{ env.FLUTTER_VERSION }}
          channel: stable
          cache: true

      - name: Firebase 설정 복원
        run: |
          echo "${{ secrets.GOOGLE_SERVICE_INFO_PLIST }}" | base64 --decode > ios/Runner/GoogleService-Info.plist
          test -s ios/Runner/GoogleService-Info.plist

      - name: 임시 키체인 생성 및 인증서 설치
        env:
          KEYCHAIN_PASSWORD: ${{ secrets.KEYCHAIN_PASSWORD }}
          IOS_CERT_PASSWORD: ${{ secrets.IOS_CERT_PASSWORD }}
        run: |
          KEYCHAIN_PATH="$RUNNER_TEMP/build.keychain-db"
          CERT_PATH="$RUNNER_TEMP/cert.p12"
          PROFILE_PATH="$RUNNER_TEMP/profile.mobileprovision"

          echo "${{ secrets.IOS_CERT_P12 }}" | base64 --decode > "$CERT_PATH"
          echo "${{ secrets.IOS_PROVISIONING_PROFILE }}" | base64 --decode > "$PROFILE_PATH"

          security create-keychain -p "$KEYCHAIN_PASSWORD" "$KEYCHAIN_PATH"
          security set-keychain-settings -lut 21600 "$KEYCHAIN_PATH"
          security unlock-keychain -p "$KEYCHAIN_PASSWORD" "$KEYCHAIN_PATH"
          security import "$CERT_PATH" -P "$IOS_CERT_PASSWORD" \
            -A -t cert -f pkcs12 -k "$KEYCHAIN_PATH"
          security set-key-partition-list -S apple-tool:,apple: -k "$KEYCHAIN_PASSWORD" "$KEYCHAIN_PATH"
          security list-keychain -d user -s "$KEYCHAIN_PATH"

          mkdir -p ~/Library/MobileDevice/Provisioning\ Profiles
          cp "$PROFILE_PATH" ~/Library/MobileDevice/Provisioning\ Profiles/

          security find-identity -v -p codesigning "$KEYCHAIN_PATH"

      - name: 의존성 설치
        run: flutter pub get

      - name: 릴리스 전 검증
        run: |
          flutter analyze --no-fatal-infos --no-fatal-warnings
          flutter test

      - name: CocoaPods 설치
        run: cd ios && bundle exec pod install --repo-update

      - name: TestFlight 업로드
        working-directory: ios
        env:
          ASC_KEY_ID: ${{ secrets.ASC_KEY_ID }}
          ASC_ISSUER_ID: ${{ secrets.ASC_ISSUER_ID }}
          ASC_KEY_CONTENT: ${{ secrets.ASC_KEY_CONTENT }}
          CI: true
        run: bundle exec fastlane beta

      - name: 키체인 정리
        if: always()
        run: security delete-keychain "$RUNNER_TEMP/build.keychain-db" || true

      - name: 산출물 보관
        if: success()
        uses: actions/upload-artifact@v4
        with:
          name: app-release-ipa
          path: build/ios/ipa/*.ipa
          retention-days: 30
```
